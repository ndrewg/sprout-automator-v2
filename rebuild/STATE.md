Also unrecorded until now: `APP_ENCRYPTION_KEY` has no documented custody, recovery or rotation path, and a backup stored beside it would be a single-file compromise of everyone's credentials. - **✅ The OTP retry path defect (found 2026-08-11, live scheduled run) is FIXED.** The original failure chain, for the record: `services/runs.ts` created **one** `AbortController` per run, aborted after the first OTP acquisition, so the retry's `pollForOtp` threw `IMAP polling aborted` without contacting Gmail — IMAP was dead for the rest of the run and the manual bridge timed out at 05:30. Compounded by `pollForOtp`'s 300 s `lookbackSeconds` default letting the first attempt accept a **stale** code already in the inbox, causing the retry. And `AggregateError.message` is always the literal `"All promises were rejected"`, which `executeQueuedRun` persisted verbatim — zero diagnostic value. **Fix:** `createOtpAcquirer` (fresh `AbortController` per attempt + per-run `submittedCodes` exclusion plumbed through `pollForOtp` → `fetchLatestOtp`) + `errorSummary` unwrapping `AggregateError` into its joined causes. Regression, unit and integration tests cover the retry path now (each proven able to fail). **Residual `[manual]` proof: a live unattended run with a stale first OTP whose retry succeeds via IMAP — the 16:15 clock-out on the operator's machine.**

- **Phases 0–5 gates are prose, not commands.** They were verified by hand at the time and are not re-runnable. `reference/testing-strategy.md` § "The high-value tests" lists what to backfill; the race guard and tenant isolation now have tests (phase T).

- **Residual (pre-existing, NOT a phase-8 regression): `X-Forwarded-For` can still rotate the auth bucket in the base direct-exposure deployment.** `TRUST_PROXY_HOPS` defaults to 1 and the base compose publishes the backend directly on `localhost:3000`, so a client that connects straight to the backend and rotates `X-Forwarded-For` gets a fresh `req.ip` (and thus a fresh rate-limit bucket) per request — the same evasion B1 described, via a different header. Recommend loopback-binding the published port (`"127.0.0.1:${BACKEND_PORT:-3000}:3000"`) and/or `TRUST_PROXY_HOPS=0` when the backend is not behind a proxy. - **✅ The `normalizePeer` / `TRUSTED_CLOUDFLARE_PEERS` footguns (tester B5, round 2) are FIXED — hardening pass 2026-08-13.** Every parsed entry now runs through the same `normalizePeer` as the socket peer (so `::ffff:172.20.0.4` in config matches a `172.20.0.4` peer and vice versa, and case differences can't silently miss); a malformed entry refuses to boot in `loadConfig()` naming its position; entries may be CIDR ranges (`172.20.0.0/16` — cloudflared's container IP decays when Docker renumbers); startup logs the set **count**; and a `CF-Connecting-IP` from a peer outside a non-empty set logs a once-only `warn` with the observed peer (never with the empty set). Message wording only; non-blocking.

- **Phase 9 (2026-08-13) additions worth knowing:**
  - **The frontend now has its own vitest** (`^4.1.10`, a devDependency) and a `pnpm test` script, so **the frontend gate is `pnpm lint && pnpm test && pnpm build && …`** — `pnpm test` runs `src/**/*.test.{ts,tsx}`. The backend stays on vitest 2.1; the two are separate packages, and the skew is intentional (frontend is on Vite 8, which needs vitest 4.1+). If you bump the frontend's `vite`, bump vitest with it.
  - **The runs-history e2e seeds rows via `app/backend/test/e2e-seed-runs.ts`** (direct `INSERT`s into `sprout_test`), because runs created through `POST /runs` would enqueue the real run executor. The seed script needs `DATABASE_URL` + `APP_ENCRYPTION_KEY` + `SESSION_SECRET` in its env — the spec supplies them.
  - **The RunsPanel count reads `Showing N`** (N = rows rendered), not "Showing N of M": the `{ runs, hasMore }` contract deliberately returns no total (no `COUNT(*)`), so "of M" is not computable while `hasMore` is true. The "Show more" button signals more exist; the count is honest and monotonic.
  - **`spawnSync` in the e2e spec and `e2e-server.mjs` emit Node's DEP0190 deprecation warning** ("shell: true with args") — harmless, pre-existing pattern, `shell: true` is required to resolve `pnpm` on Windows.
  - **CI coverage fact (2026-08-14, not a defect):** `pnpm test:integration` and `pnpm test:e2e` run **nowhere in CI** — the backend job stops at unit `test`, the frontend job has no e2e. The next session must not assume CI exercises integration or e2e (it is a typecheck + lint + unit-test gate only).
  - **Seed helper guard is loose by design (F2, 2026-08-14):** `app/backend/test/e2e-seed-runs.ts` refuses to seed unless `current_database()`'s name `includes("test")` (verified before the INSERT, exit 1 against `sprout`). The substring rule is **not** a tight match — a database named `latest`, `contest`, or `sprout_prototype` would also pass. It is a guard against *accident* (a bare invocation with a dev/prod `DATABASE_URL` fabricating history), not against a *deliberately-named* database; the realistic risk (a human pointing it at the real `sprout`) is blocked. Tighten to exact `sprout_test` / `_test`-suffix only when the helper is next touched (see `BACKLOG.md`).

## Conventions that changed after the phase docs were written

- **Audience.** Phases 0–5 were written for a quantized local model driven one phase per session. The build now targets a hosted agentic model (see `00-START-HERE.md` § "Model & runtime"). Phases 0–5 are kept **as an as-built record** — don't rewrite them; they document what was done and why.
- **Gates.** New phases state gates as commands with exit codes, marking human-only checks `[manual]`. See `reference/testing-strategy.md`.
- **Tests** live in `test/` mirroring `src/`, not colocated (commit `8c3d226`).
- **Test layout (phase T):** `test/lib/**`, `test/services/**` are the database-free `unit` vitest project (`pnpm test`); `test/integration/**` is the `integration` project against `sprout_test` (`pnpm test:integration`, single fork so the shared DB is never truncated concurrently). E2E lives in `app/frontend/e2e/` (`pnpm test:e2e`), driven by a `webServer` that builds the SPA into `app/backend/public`, migrates `sprout_test`, and boots the real backend.
- **Vitest config (phase 10, 2026-08-24):** backend is on vitest **4.1.11** and the two projects now live in `vitest.config.ts` under `test.projects` — the `vitest.workspace.ts` file was deleted (vitest 4 removed it). The integration project's serial execution is `maxWorkers: 1` (the old `poolOptions.forks.singleFork` was removed in vitest 4). `vite` is an explicit backend devDependency (`^8.2.2`) — a stale lockfile had resolved vitest 4's `^6||^7||^8` vite peer to the old 5.4.21, which `pnpm peers check` flags; keep the explicit dep if you ever touch vite here. **pnpm 11 quirk to remember:** adding `overrides:` to `pnpm-workspace.yaml` does NOT trigger re-resolution on `pnpm install` (reports "Already up to date") — run `pnpm update <transitive>` once to force the overridden edges to re-resolve.
